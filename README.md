# КЛЁВ — GitHub Pages + Supabase

Это отдельная версия без Python-сервера. Только эта папка предназначена для публикации через GitHub Pages. Python-файлы из предыдущего проекта здесь не нужны. Сейчас база ещё не подключена: config.js содержит пустые значения, чат и регистрация показывают уведомление, а не подставные данные.

В config.js допускаются ТОЛЬКО публичный адрес проекта Supabase и publishable ключ (или legacy anon JWT). НЕ пароль БД, НЕ строка PostgreSQL, НЕ secret/service_role ключ. Публикация браузерного ключа сама по себе допустима, но безопасна только при правильных серверных политиках RLS и grants. Никогда не публикуйте секретные ключи; если это уже произошло, их нужно заменить в Supabase.

Обязательная настройка перед регистрацией пользователей:
1. Выполнить setup.sql из отдельного комплекта настройки в Supabase SQL Editor.
2. Включить Data API для схемы public. Автоматическое раскрытие всех новых таблиц не включать. Раньше для Python-сервера Data API отключали; для ЭТОЙ версии он нужен.
3. Заполнить config.js публичными значениями из Supabase Settings → API Keys/Connect.
4. В Supabase Auth → URL Configuration указать адрес сайта GitHub Pages в Site URL и точный разрешённый redirect URL. Включить Email provider и подтверждение email. Подключить SMTP, пригодный для реальных пользователей: встроенная тестовая почта Supabase ограничена по частоте и разрешённым получателям, массовая регистрация с ней не гарантируется. Нет собственного интерфейса восстановления пароля.
5. Убедиться двумя разными тестовыми аккаунтами, что профиль и дневник приватны, чат общий, неподтверждённая почта не даёт доступ, а аноним не может читать ни одну из трёх таблиц.

Данные хранятся в Supabase, код — на GitHub Pages. В отличие от прежней версии, вход сохраняется в браузерном localStorage, а пароль обрабатывает Supabase Auth. XSS может украсть токены, поэтому не добавляйте непроверенные скрипты. На общих компьютерах выходите из аккаунта. Если храните другие сайты на том же домене GitHub Pages, учитывайте общий origin/localStorage. Сообщения экранируются, внешние JS-библиотеки не используются, в HTML задан CSP.

Профиль и уловы доступны только их владельцу по RLS. В чате сохранены имя и город автора на момент сообщения; последующая смена профиля не переименовывает старые сообщения. При удалении аккаунта удаляются его сообщения, профиль и уловы. SQL-функция удаления работает только с auth.uid(), а интерфейс дополнительно просит повторить пароль. Доступ в 7 дней не ограничен; встроенных оплат нет.

Бесплатные тарифы имеют лимиты и не гарантируют постоянную работу. Подготовленный сайт пока НЕ прошёл проверку с настоящим облачным проектом. Нет модерации, жалоб, банов и production-аудита. Ограничитель чата на стороне БД — 8 сообщений за 30 сек. на пользователя; регистрационный антибот и общие квоты требуют отдельной настройки. Для роста нужно перейти с опроса раз в 3 секунды на Realtime. Перед публичным запуском необходимы юридические документы, контакты оператора, проверка локализации персональных данных, резервные копии и восстановление пароля. Для первого теста используйте вымышленные данные небольшой группы.
